The verified panel — a second, later review pass

The ticket already carries a plan review. The problem is making the verification read as a different kind of review rather than a second copy of the first. Four things do the work: both panels sit on a lifecycle rail in chronological order, so position alone says which came first; each carries a numbered pass badge (Pass 1 · Plan review, purple and past-tense; Pass 2 · Verification, coral and live); the plan panel is collapsed and settled while the verification panel is expanded and re-runnable; and only the verification panel has an environment strip — a plan review has no build to point at, a verification is nothing without one.

SWY-268

Search results should surface recent tickets above stale exact matches

ClosedbackendlyceumEpic · SWY-260 Search relevance
Description

Search currently ranks purely on lexical relevance, so a ticket closed two years ago with the exact phrase in its title beats the ticket someone touched this morning. Add a recency term to the ranking function, keep exact key lookups short-circuited, and put the whole thing behind a flag so prod can stay on the old behaviour until we are sure.

Acceptance criteria
A ticket updated in the last 7 days outranks an older ticket with an identical title match.
Exact key matches always rank first, regardless of age.
Search p95 stays under 400ms with the recency term added.
The ranking change sits behind lyceum.recency_rank and is off by default in prod.
