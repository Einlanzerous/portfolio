Insights · cost & effectiveness

What the work cost, and whether it was worth it

The current page answers how much did we spend and stops there. Three changes make it answer the question actually being asked. Money reads twice — notional list price as the measuring stick, the flat plan allocated by share as the real figure, so “Switchyard cost $59.35 this month” is a sentence the page can say. Work is the denominator — tickets closed, plan→ship cycles, first-try verifications, closures with no human turn. A run belongs to a job class, which is what makes two projects comparable at all.

Local weights are first-class rather than an afterthought: they cannot be plotted at $0 without lying, so they sit in their own band on the cost axis and get a share-of-calls ribbon under the spend chart. Anything the data cannot support is drawn as a dashed card naming the ticket that would fix it — the honest empty is better than a tile reading 0.0% forever.

Reuses delivery.css primitives throughout — .vsw, .banner, .tref, .chip, .status-pill, .mix. New: a six-hue model palette keyed to entity, not rank, per SWY-321.

Job classes
A run belongs to a class of work, and the class is what makes two projects comparable. pr-review is the clearest case: the same model, the same trigger, the same standard prompt — so anything that differs between projects is the guidance, not the machine.
Label coverage

explicit 38%inferred 24%derived 11%manual 0%unlabelled 27%
1explicitThe invoker sets job_class on the run. Containers spawned from a ticket already do this.
2inferredFrom the automation or ticket that spawned it — the link exists, it is just not projected onto the run.
3derivedFrom the workflow identity and prompt fingerprint. This is the one that backfills.
4manualA human tags a run after the fact. Built, deliberately unused — an escape hatch, not a workflow.
31,412 CI runs can be labelled retroactively — no producer change
Every pr-review is a GitHub Actions step running claude-code against .github/prompts/review.md. Two signals already sit on every one of those rows: runner = github-actions and a stable system-prompt fingerprint sha256:9f2c81…. Matching on the pair recovers the class, the project (from the workflow’s repo, not the detached HEAD), and the prompt revision — back to the first run on 2026-07-18. It also collapses roughly two-thirds of the 37% ambient block.
